# Почему десктоп нельзя выпустить прямо сейчас — три блокера сборки

KQ-R2 требует обновить десктопные загрузки: на сайте v0.2.12, а в дереве месяцы исправлений, включая
две дыры в памяти toxext. Формулировка отчёта предполагает, что сборку просто не делали.

Причина другая: **сборка десктопа на современной macOS не проходит вообще**. Проверено попыткой
собрать — три блокера подряд, каждый останавливает раньше следующего.

## 1. CMake 4 отказывается конфигурировать старые проекты — обходится

`cmake_minimum_required(VERSION < 3.5)` в qrencode и соседях. CMake 4.3 такие проекты не берёт.

**Обход найден и проверен:** переменная окружения `CMAKE_POLICY_VERSION_MINIMUM=3.5` работает —
подтверждено на минимальном примере, а не предположено.

## 2. Патч vpx для macOS устарел на две версии — исправлено

`buildscripts/patches/vpx-macos.patch` написан в 2022 году. Сейчас `download_vpx.sh` качает **1.14.1**,
где целевой блок сместился с ~869-й строки на ~936-ю. `patch(1)` его отвергает, а `build_vpx.sh`
работает под `set -e` — сборка зависимостей умирает там, до vpx, opus, ffmpeg, toxcore и приложения
дело не доходит.

Патч пересоздан под 1.14.1. Смысл прежний: убрать блок `-mmacosx-version-min`, прибивающий целевые
версии 10.4–10.12; на darwin24 ни одна его ветка не срабатывает, это мёртвый код, который мешает
современному SDK.

## 3. vpx конфигурируется как `generic-gnu` — НЕ исправлено

После второго исправления сборка дошла дальше и упала на линковке:

```
[LD] libvpx.so.9.0.1
ld: unknown options: -z -soname --version-script
Configuring for target 'generic-gnu'
```

`libvpx.so` — ELF-имя: vpx не распознал платформу и собирается как Linux, поэтому передаёт линкеру
ELF-опции, которых в macOS `ld` нет. `build_vpx.sh` задаёт `--target` только для Windows
(`x86_64-win64-gcc` / `x86-win32-gcc`), а для macOS полагается на автоопределение — и оно не
срабатывает.

**Почему не исправлено здесь.** Правка означает явный `--target` для macOS, то есть изменение того,
как собирается выпускаемый бинарник. Это надо проверять сборкой на всех трёх платформах, а не
подбирать вслепую — и, судя по тому, что первые два блокера обнаружились подряд, за третьим вероятны
следующие (ffmpeg, toxcore, Qt-линковка).

## Что это значит для KQ-R2

Задача не «собрать и выложить», а **починить сборочную цепочку десктопа под современные
macOS-инструменты**. Два из трёх блокеров закрыты, третий диагностирован точно.

Пока это не сделано, исправления toxext (утечка памяти процесса в окно чата) до пользователей
десктопа не доходят — и это следует считать открытым, а не отложенным.
